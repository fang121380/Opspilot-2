# UI 审计 / UI Audit

## 用户和主任务

用户是零基础学习者。首屏必须回答：这是学什么的、为什么按这个顺序、现在只需要点哪里。主任务是完成五课，不是直接操作集群。

## 本轮发现与处理

| 优先级 | 问题 | 处理结果 |
| --- | --- | --- |
| P0 | 课程可直接点击完成，没有学习证据 | 改为概念、三条命令、自检、小测四项门槛 |
| P0 | 多条课程预置命令被终端白名单误拦截 | 补齐五课全部 15 条命令及对应输出 |
| P1 | 切换课程时命令状态可能沿用上一课 | 命令直接由当前课程数据驱动，不再维护冲突的下拉状态 |
| P1 | 5/5 后首页仍提示继续第五课 | 改为“课程完成，查看真实集群” |
| P1 | 事故字段使用 `title`，后端实际返回 `alert_name/summary` | 对齐真实 API 数据模型 |
| P1 | 桌面启动器只启动前端，“连接实机”可能不可用 | 同时启动本地只读 `lab-api` |
| P1 | 2560 全屏文字小、内容区域窄 | 大屏提升字号和最大内容宽度 |
| P1 | 窄窗口侧栏与内容争抢空间 | 1000px 以下收为抽屉，课程和流程改为自适应布局 |
| P2 | 无事件时显示成普通事件文本 | 改为解释原因和下一步的空状态 |
| P2 | 新手看不懂资源、事件、日志的差别 | 集群页新增通俗解释带 |

## 状态和风险

已覆盖 loading、empty、error、disabled、selected、completed、wrong answer 和 needs-review。终端只运行内置模拟白名单；未知命令、写操作、管道和重定向不会执行到本机。集群连接只读取固定 `kind-k8s-lab` context。回滚仍由 Opspilot 服务端人工审批门控制。

## 响应式

电脑端重点验证 2560×1373、1440×1000、1024×820 和 800×800。800px 时侧栏变为菜单；表格只有自身允许横向滚动，页面本身不横向溢出。额外完成 390px 自动检查，保证意外小屏访问不会破版。
