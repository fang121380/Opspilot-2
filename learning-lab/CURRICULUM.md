# 应用学习链：从容器到证据驱动排障

这条路径按知识依赖安排 30 课：学习准备 1 课、Docker 9 课、Kind 5 课、Kubernetes 11 课、综合排障 4 课，其中 25 节深入课包含分析任务和自评。目标是独立解释、交付和诊断一个容器应用。先阅读原理，再检查模拟快照，完成情景小测和应用任务；六份实机手册用于手工验收。旧五课成绩可继续使用，不代表新章节已经完成。

课程时长是阅读、练习与任务的建议预算，不含首次安装、镜像下载、独立实机专题和反复排障；可以分多天学习。首页支持章节与学习状态筛选，搜索正文、术语和命令；可以把暂时不熟的课程标为待复习，完成成绩仍保留。分析笔记可导出 Markdown 阅读和备份，不能导入、恢复完整进度或跨设备同步。

## 学习准备

区分工具、运行环境和操作目标。

阶段验收：能解释客户端版本为何不能证明环境可用。

### 1. 环境检查（10 分钟）

- 先修：无
- 学习结果：读懂三个工具的模拟版本输出，区分客户端存在、容器引擎可用和集群连通。
- 关键知识：Docker、Kind、kubectl

## Docker：从进程到多服务

理解容器生命周期，构建镜像，连接网络和存储，组织多服务。

阶段验收：交付可重复构建、可访问、可诊断的容器应用。

### 2. Docker 基础（25 分钟）

- 先修：环境检查
- 学习结果：从模拟输出解释镜像、容器，以及临时容器退出后的清理行为。
- 关键知识：镜像 Image、容器 Container、端口 Port

### 3. 容器生命周期与进程（40 分钟）

- 先修：Docker 基础
- 学习结果：结合状态、退出码和日志，区分正常结束、应用失败与尚未证实的资源问题。
- 关键知识：PID 1、退出码、容器可写层
- 应用任务：写一份三句故障记录，解释 lab-worker 为什么没有持续运行。

### 4. 从源码构建可复现镜像（55 分钟）

- 先修：容器生命周期与进程
- 学习结果：读懂一个 Dockerfile，判断哪些输入变化会使缓存失效，并用镜像身份核对运行版本。
- 关键知识：构建上下文、构建缓存、镜像 digest
- 应用任务：给一个源码频繁修改的服务设计构建与版本核验流程。

### 5. 多阶段构建与运行产物（60 分钟）

- 先修：从源码构建可复现镜像
- 学习结果：解释多阶段复制的对象，识别静态程序、平台和非 root 运行的约束，并用独立 HTTP 实验验证交付。
- 关键知识：构建阶段、静态二进制、运行契约
- 应用任务：画出源码到 HTTP 响应的交付链，并为这个最小镜像写一份运行契约。

### 6. 镜像仓库与版本交付（65 分钟）

- 先修：多阶段构建与运行产物
- 学习结果：解释 tag、push、pull 和 digest 的作用，设计有来源记录、权限边界和运行验收的镜像交付。
- 关键知识：tag、manifest digest、registry
- 应用任务：给另一个学习环境写一份可复核的镜像交付单，并标出当前本机仓库的适用边界。

### 7. 容器网络与访问路径（50 分钟）

- 先修：镜像仓库与版本交付
- 学习结果：画出电脑、手机和容器的请求路径，解释 localhost 的范围及服务名称解析条件。
- 关键知识：回环地址、端口发布、用户自定义 bridge
- 应用任务：为“电脑能打开、手机打不开”写一个有顺序的检查清单。

### 8. 数据持久化与配置挂载（50 分钟）

- 先修：容器网络与访问路径
- 学习结果：从 Mounts 识别命名卷与绑定挂载，解释删除实例后的数据边界，并制定备份验证办法。
- 关键知识：命名卷 Volume、绑定挂载 Bind mount、恢复验证
- 应用任务：为数据库容器升级写一个不丢数据的准备方案。

### 9. Compose 编排一个应用栈（60 分钟）

- 先修：数据持久化与配置挂载
- 学习结果：解释 Compose 服务依赖与健康检查，分清进程启动、依赖就绪和业务可用。
- 关键知识：Compose 项目、healthcheck、service_healthy
- 应用任务：把“先启 Redis，再启 Web”的口头要求变成可检验方案。

### 10. Docker 综合验收（60 分钟）

- 先修：Compose 编排一个应用栈
- 学习结果：独立建立镜像、进程、网络、存储与请求五层检查链，为迁移 Kind 准备证据。
- 关键知识：证据链、最小权限、交付验收
- 应用任务：提交一份可供同学接手的 Docker 阶段验收记录。

## Kind：搭建可复现的实验环境

理解节点与宿主机关系，配置集群、装载镜像并管理生命周期。

阶段验收：能将本地镜像送入指定学习集群，并说明重建会丢失什么。

### 11. Kind 集群（30 分钟）

- 先修：Docker 综合验收
- 学习结果：读懂模拟 context、节点和命名空间输出，知道如何显式指定学习集群。
- 关键知识：Cluster、Node、Context、Namespace

### 12. Kind 架构与三层边界（45 分钟）

- 先修：Kind 集群
- 学习结果：解释 Kind 节点为什么是容器，区分 Docker 引擎、节点运行时和 Kubernetes API。
- 关键知识：控制平面、kubelet、容器运行时
- 应用任务：画出从 kubectl 查询到 Pod 运行的职责图。

### 13. 用配置声明学习集群（55 分钟）

- 先修：Kind 架构与三层边界
- 学习结果：读懂 Kind 配置并解释创建时配置、节点端口映射和 Kubernetes Service 的关系。
- 关键知识：Kind 配置文件、extraPortMappings、API server 入口
- 应用任务：解释一个本机网页入口，并指出手机访问的限制。

### 14. 把本地镜像交给节点（50 分钟）

- 先修：用配置声明学习集群
- 学习结果：根据 Pod 事件区分主机镜像存在与节点可用，设计不依赖 latest 的本地发布流程。
- 关键知识：节点镜像存储、imagePullPolicy、ImagePullBackOff
- 应用任务：写出从本地 v3 镜像到 Kind Pod 可运行的完整核验链。

### 15. 实验集群的保存、重建与验收（55 分钟）

- 先修：把本地镜像交给节点
- 学习结果：区分上下文记录与真实集群存活，制定有数据边界、恢复顺序与验收条件的重建计划。
- 关键知识：kubeconfig、声明恢复、重建基线
- 应用任务：为同学准备一份可安全执行的学习集群重建清单。

## Kubernetes：管理应用的整个生命周期

从声明式对象走到发布、网络、配置、存储、健康检查和权限。

阶段验收：能解释从配置到 Pod、Service 和请求的完整路径。

### 16. 读懂应用部署（35 分钟）

- 先修：实验集群的保存、重建与验收
- 学习结果：检查预先部署应用的模拟证据，区分副本就绪、Pod 运行与 Service 入口。
- 关键知识：Pod、Deployment、Service

### 17. 声明式部署与协调循环（40 分钟）

- 先修：读懂应用部署
- 学习结果：读懂 Deployment 清单，区分 spec 与 status，解释副本暂时不一致的原因。
- 关键知识：spec、status、协调循环
- 应用任务：为这次部署写一份三句状态报告。

### 18. 工作负载与滚动发布（45 分钟）

- 先修：声明式部署与协调循环
- 学习结果：解释新旧 ReplicaSet 共存，选择合适工作负载，并判断滚动更新为何卡住。
- 关键知识：ReplicaSet、Label / selector、RollingUpdate
- 应用任务：设计一次两副本网站的滚动发布验收单。

### 19. 一次性任务与定时任务（45 分钟）

- 先修：工作负载与滚动发布
- 学习结果：为报表任务选择控制器，区分任务完成、业务成功与重复执行，并设计可验证的重试策略。
- 关键知识：Job、幂等、CronJob
- 应用任务：为每天 UTC 02:00 生成前一天报表的任务写一份执行与验收方案。

### 20. Service、DNS 与流量路径（45 分钟）

- 先修：工作负载与滚动发布
- 学习结果：连接 Service selector、Pod 标签、targetPort 与 EndpointSlice，区分集群内外访问。
- 关键知识：targetPort、EndpointSlice、Service DNS
- 应用任务：为同命名空间客户端写出访问 hello-web 的完整路径。

### 21. 配置与 Secret 的生命周期（40 分钟）

- 先修：Service、DNS 与流量路径
- 学习结果：区分环境变量和文件挂载的更新行为，设计不泄露凭据的配置验证。
- 关键知识：ConfigMap、Secret、配置生效方式
- 应用任务：为日志级别变更编写安全的发布与回退计划。

### 22. 存储与数据生命周期（45 分钟）

- 先修：配置与 Secret 的生命周期
- 学习结果：解释 Pod 重建与数据持久化的关系，读懂 PVC 绑定和 PV 回收策略。
- 关键知识：PVC、PV、回收策略
- 应用任务：给上传文件服务选择存储，并写出生命周期说明。

### 23. 有状态应用与稳定身份（50 分钟）

- 先修：存储与数据生命周期
- 学习结果：追踪一个 Pod 替换前后的名字与存储，解释有序更新为何会停住，并划清持久化与数据库高可用的边界。
- 关键知识：StatefulSet、Headless Service、volumeClaimTemplates
- 应用任务：给两个有独立数据目录的成员画出身份、服务与卷的对应关系，并制定替换后的验收。

### 24. 启动、存活与就绪探针（40 分钟）

- 先修：存储与数据生命周期
- 学习结果：根据故障表现选择探针，解释 Running、Ready 和重启次数为何不同。
- 关键知识：startupProbe、livenessProbe、readinessProbe
- 应用任务：为启动耗时较长的网站设计三种探针职责。

### 25. 资源、调度与 OOM（45 分钟）

- 先修：启动、存活与就绪探针
- 学习结果：区分调度资源不足、CPU 限流与内存超限，避免用同一种重启处理所有问题。
- 关键知识：requests、limits、OOMKilled
- 应用任务：为两个故障分别写一个待验证假设和最小调整计划。

### 26. 身份、RBAC 与最小权限（40 分钟）

- 先修：资源、调度与 OOM
- 学习结果：区分认证和授权，读懂 Role 与 RoleBinding，并检查只读身份的权限边界。
- 关键知识：ServiceAccount、RBAC、最小权限
- 应用任务：为 learning 命名空间的 Pod 排障助手写一份权限申请。

## 综合排障：用证据验证判断

串联状态、事件、日志和流量，区分启动、就绪与网络故障。

阶段验收：提交包含现象、证据、假设、最小修复和验证的事故记录。

### 27. 故障排查（45 分钟）

- 先修：身份、RBAC 与最小权限
- 学习结果：结合应用部署课的状态快照，阅读模拟事件、日志和详情，形成待验证的故障假设。
- 关键知识：Pod phase、Event、Log、describe

### 28. 启动故障分诊（50 分钟）

- 先修：故障排查
- 学习结果：根据容器启动进度选择事件、镜像信息或上次日志，形成有证据的假设。
- 关键知识：FailedScheduling、ImagePullBackOff、CrashLoopBackOff
- 应用任务：分别为三份快照填写“环节—证据—下一步”。

### 29. 网络故障的证据链（50 分钟）

- 先修：启动故障分诊
- 学习结果：用最短证据链定位 Service 无后端，避免把所有转圈问题归因于 DNS。
- 关键知识：访问位置、空端点、证据链
- 应用任务：写一份 broken-web 的故障记录与恢复验收。

### 30. 综合演练：发布故障与恢复验证（60 分钟）

- 先修：网络故障的证据链
- 学习结果：独立写出可审阅的故障结论、回退提案和验收条件，知道哪些结论仍缺证据。
- 关键知识：回退提案、恢复验收、变更边界
- 应用任务：提交一份可由同伴审阅的事故处理单。

## 实机项目如何衔接

1. [Docker](labs/05-docker-project.md)：构建小网站，验证端口与数据，补充 Compose 和服务网络。
2. [镜像交付](labs/09-image-delivery.md)：使用独立 Go HTTP 服务练习多阶段构建、非 root 运行、缓存、本机临时仓库及真实摘要交付，不覆盖前一项目的镜像。
3. [Kind](labs/06-kind-project.md)：复用学习集群并装载原有网站镜像，检查节点运行时；不直接使用主机回环仓库地址作为节点入口。
4. [Kubernetes](labs/07-kubernetes-project.md)：部署 study-web，验证更新、配置、存储、探针和最小权限。
5. [工作负载模式](labs/10-workload-patterns.md)：在 `learning` 命名空间使用专用资源名称练习 Job/CronJob、StatefulSet 的稳定身份与存储。
6. [排障](labs/08-troubleshooting-project.md)：手工引入故障，保留证据，恢复并复验。

网页固定快照、个人自评与实机结果分别记录。模拟场景里的资源名称不要求与实机项目相同，重点是字段含义和验证方法。请保留一个实机记录：版本/目标、操作、现象、证据、假设、修复、复验、未解决项。

新增镜像交付与工作负载模式手册的真实实验尚未执行。Go 源码编译和 YAML 解析只验证材料，不代表 Docker、Job 调度或存储恢复已在集群通过。实际验证范围见[本轮学习改进记录](../docs/learning-improvements-2026-09-10.md)。

## 后续深化边界

本路径串联一个应用的交付与排障，不等于 Kubernetes 全领域或认证考试课程。Job/CronJob 与 StatefulSet 已增加独立课程；DaemonSet 仍只有工作负载选择层面的介绍，没有独立实机实验。复杂生产部署仍需额外验证。

下一轮按依赖顺序推进：

1. **Ingress 入口**：先弄清 Service 与入口控制器职责，验证主机名、路由与 TLS 的访问路径。
2. **HPA 指标**：在资源 requests/limits 基础上认识指标来源，再验证扩缩容触发条件与延迟。
3. **NetworkPolicy**：确认实验 CNI 实际支持策略后，再练习默认拒绝、DNS 放行和按应用开放流量。
4. **Helm/GitOps**：建立可验证的部署、配置和访问基线后，再学习模板、版本管理与持续协调。

这些是后续专题，不作为本轮已完成课程。生产高可用、服务网格、集群升级与备份恢复工程也仍需独立学习与实机验收。
